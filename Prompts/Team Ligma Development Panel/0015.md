# Prompt
Does this also make the active outside build show up as a running build elsewhere in the panel, and show the peroper metrics, etc?

# Reponse
Yes. Verified on v1.7.6 with the command `screen -dmS build ninja-dash <dir> -- -j8 -k 0` (no code changes this round).

**Started through the runner (as root, or any user who can write to panel-data)**, it is a full panel build with the same data as Start Build:
- Overview tab, sidebar "at a glance", Build Console dropdown and History all list it as running.
- Progress comes from ninja's own status lines (e.g. 4 / 8), along with the current step and the objects being compiled with elapsed and estimated times.
- The Build Console terminal shows the full live build and install output.
- Start/Prepare/Clean in that directory are blocked while it runs.
- Force Stop works (recorded as "Stopped by user"). The `ninja install` step runs automatically after a successful build, as with panel builds.

**Started by a user who can't write to panel-data**, the build runs without a record and is followed as an external build. It also appears everywhere, with progress counted from `.ninja_log`, exact totals (isolated dry run), the objects being compiled, and Force Stop. The differences:
- the terminal lists finished steps rather than full compiler output;
- the result (Completed / Failed) is worked out after the build ends;
- steps finished before the panel noticed it aren't counted.

**Not applied to outside builds:** the CPU threads setting (the command's own `-j8` is used).

**Note:** one run showed an external build counted 4 of its 6 steps. Three further attempts, including one under the same conditions, counted correctly, so I couldn't reproduce or pin down the cause. The build's result was correct either way.
