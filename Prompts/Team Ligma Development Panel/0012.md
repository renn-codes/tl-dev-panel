# Prompt
The volumes should be named after the output version string

(Clarified: name them after the AzerothCore version.) Use the suffix scheme

# Reponse
Portainer volumes for successful builds are now named after the AzerothCore version, with a suffix for repeat builds (v1.7.3).

- `build.sh` prints the AzerothCore version (from `acore.json`, or the commit) as a `##tl-version` marker, and records it in `BUILD_INFO.txt`.
- The first build of a version gets `15.0.0-dev`, later ones `15.0.0-dev_2`, `15.0.0-dev_3`, … Numbering continues after the highest suffix in use, so a deleted name is never handed to a newer build. Builds finishing at the same time are serialized, and the panel checks the volume it created really points at its own folder.
- A `com.teamligma.version` label is added. The output folder keeps its full `<version>_<time>_<commit>` name.
- With an image built from the old `build.sh`, the name falls back to the folder name's part before its first `_`.

**Tested against Portainer:** three builds gave `15.0.0-dev`, `_2`, `_3`; after deleting `_2` the next got `_4`; two builds finishing together got `_5` and `_6`; an unrelated `15.0.0-dev_foo` volume was ignored; the marker doesn't appear in the log.

Rebuild the builder image so it includes the new `build.sh`.
