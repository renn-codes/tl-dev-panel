[Screenshot of the "Ninja processes on this server" dialog: pid 4334, "Panel build", user claude, command `ninja -j8 -k 0` in /roc/claude/claude-acore/build, reason "run by ninja-dash, which records the build itself".]

# Reponse
Fixed: builds run by your own ninja-dash are now followed (v1.7.4).

**Cause:** the screenshot showed the build being skipped as "run by ninja-dash, which records the build itself", but no record appeared. The `ninja-dash` on your server that started it (`ninja -j8 -k 0`, user claude: the original directive command) is your own tool, not the panel's runner, so it doesn't write panel records. The detection trusted any process named ninja-dash, so the build fell into a gap.

**Fix:** a ninja process now counts as a panel build only when one of its ancestors is a *running, recorded* panel build (the ninja-dash pid in a live build record), or the panel itself. Any other ninja-dash, such as yours or one run by another user, is followed as an external build.

**Tested:**
- Your setup recreated: user `claudetest` ran their own `ninja-dash` via `screen -dmS build ninja-dash <dir> -- -j8 -k 0`, with ninja-dash staying alive as ninja's parent. Before the fix this was skipped; now it's followed as an external build.
- A panel build running at the same time was still recognised as the panel's own and not recorded twice.

Test builds, the test user and the test account were removed.
