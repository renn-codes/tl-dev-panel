# Documentation Guidelines
This skill is relavent to this module's documentation standards. It details Versioning, Coherency, and Branding.

## Versioning
When creating and/or updating a module/map project, the project should be versioned in the format of A.B.CC, where A is major, B is minor, and CC is revision (with a second digit after it reaches double digits). The revision number is allowed to go into two digits, if a minor version increment isn't needed, and should be kept in mind for version incrementation. Version only when the scope of changes would deem appropriate.

## Coherency
Keep documentation focused and concise. Reasoning and background for feature design, changes, etc is not needed, but guides on set-up, use, and instuctional material are necessary. Keep project descriptions and other appropriate text blocks moderately flavorful.

## Branding
Each documentation file should have branding utilizing the logo located at `claude/teamligma.png` and the following text at the end:

`Created and maintained by Team Ligma. This content can be used for non-commercial use, with attribution.`
